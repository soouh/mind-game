## 프로젝트 소개

**내 마음이 들리니 — AI 스무고개 밤티공방**은 사용자가 마음속으로 정한 대상을 AI가 최대 20개의 질문으로 추리하는 웹 게임입니다.

사용자는 동물·음식·물건·아무거나 중 하나를 선택해 게임을 시작합니다. 너구리 장인이 질문을 던지면 사용자는 **[응] [아니] [모르겠어]** 버튼으로 답합니다. AI는 답변 기록을 바탕으로 추리 범위를 좁혀 정답을 맞히려고 합니다. AI가 정답을 추측하면 완성품이 도트 그림으로 등장하고, 사용자는 결과가 맞는지 확인한 뒤 새 주문에 도전할 수 있습니다.

## 기획 의도와 콘셉트

### 밤티공방: 서툴지만 정감 있는 AI 공방

밤티공방은 초보 너구리 장인이 손님의 주문을 받아 물건을 만들어 주는 가상의 공방입니다. AI가 정답을 맞히더라도 결과 그림이 늘 완벽한 것은 아닙니다. 감자튀김이 노란 네모처럼 보이거나 국밥 이미지가 기대와 다르게 생성되는 경우도 있습니다.

이런 어설픈 결과를 단순한 오류로만 취급하기보다 **초보 장인이 운영하는 공방이라는 세계관의 유머**로 연결했습니다. 다만 게임을 방해하는 기능 오류는 개선 대상으로 구분합니다.

### 기획 목표
- AI와 대화하며 정답을 추리하는 가벼운 놀이 경험 제공
- 픽셀 아트와 너구리 캐릭터를 활용한 개성 있는 서비스 디자인
- 질문 생성과 도트 이미지 생성 기능을 실제 웹 서비스에 연결
- 모바일에서도 편하게 이용할 수 있는 화면 구성
- AI 결과의 불완전함을 서비스의 유머와 개성으로 활용

## 주요 기능

### 1. 주문 종류 선택
게임 시작 전 **동물 / 음식 / 물건 / 아무거나** 중 하나를 선택합니다.

### 2. AI 스무고개
- AI가 질문을 제시하고 사용자가 답변합니다.
- 사용자는 **[응] [아니] [모르겠어]** 버튼으로 답할 수 있습니다.
- 답변은 주문서에 기록되어 추리의 근거로 활용됩니다.
- 남은 질문 횟수를 화면에 표시합니다.
- AI가 정답을 추측하면 완성품을 보여 줍니다.

### 3. 너구리 장인 애니메이션
AI가 답을 생각하는 동안 너구리 장인이 망치를 휘두르며 '뚝딱뚝딱' 작업합니다. 몸통과 망치를 든 팔을 분리해 팔이 회전하도록 구성했습니다.

- **제작 중:** 망치를 들고 내리치는 동작, 집중선과 불꽃
- **성공:** 활짝 웃는 표정, 햇살과 꽃가루 효과
- **실패:** 긁적이는 표정, 먹구름과 보슬비 효과

완성품이 틀렸거나 오류가 발생한 경우에도 실패 상태를 시각적으로 보여 줍니다.

### 4. 도트 그림으로 완성품 표현
AI가 정답을 추측하면 완성품이 '따란!' 하고 등장합니다. 사용자는 **[응, 마음에 들어!]** 또는 **[아니, 이게 아니야]**로 결과를 확인합니다.

- 대상과 잘 맞는 이모지가 있으면 이모지를 도트 그림으로 변환해 표시합니다.
- 적절한 이모지가 없으면 Gemini API가 16×16 도트 그림을 생성합니다.
- 생성 그림은 색상 팔레트와 픽셀 배열 데이터로 전달됩니다.
- 서버에서 그림 크기와 색상 형식을 검사합니다.
- 그림 생성에 실패하거나 결과 형식이 유효하지 않으면 유사한 이모지 그림으로 대체합니다.

### 5. 오류 안내와 재시도
- 종류 미선택 시 안내
- API 오류 발생 시 오류 상황 안내
- 요청이 오래 걸릴 때 지연 안내
- 요청 타임아웃 처리
- 서버 혼잡 시 자동 재시도
- 새 게임 시작 동선 제공

## 이용 방법
1. [서비스 페이지](https://mind-game-pink.vercel.app)에 접속합니다.
2. 메인 화면에서 게임을 시작합니다.
3. 동물·음식·물건·아무거나 중 주문 종류를 선택합니다.
4. 마음속으로 맞힐 대상을 정합니다.
5. 너구리 장인의 질문에 응·아니·모르겠어로 답합니다.
6. AI가 정답을 추측하면 완성품 도트 그림을 확인합니다.
7. 정답 여부를 선택하고 원하면 새 주문을 시작합니다.

## 동작 흐름
1. 사용자가 종류를 선택하고 답변 버튼을 누릅니다.
2. `js/game.js`가 카테고리와 질문·답변 기록을 `fetch('/api/game')`로 보냅니다.
3. `api/game.py`가 요청 기록을 검사한 뒤 Groq API에 다음 질문을 요청합니다.
4. 질문이 생성되면 프런트엔드에 전달해 화면에 표시합니다.
5. AI가 정답을 추측하면 필요에 따라 Gemini API를 호출해 완성품 그림을 생성합니다.
6. 응답이 화면에 표시되고 사용자가 결과를 확인합니다.

AI 모델이 이전 요청을 자동으로 기억한다고 가정하지 않습니다. 각 요청에는 추리에 필요한 질문과 답변 기록을 함께 전달합니다.

질문 응답 예시:

```json
{
  "type": "question",
  "text": "동물이야?"
}
```

정답 추측 응답 예시:

```json
{
  "type": "guess",
  "item": "단호박 수프",
  "emoji": "🍲",
  "palette": {},
  "pixels": []
}
```

예시는 응답 구조를 설명하기 위한 것으로, 실제 픽셀 배열에는 16×16 그림 데이터가 들어갑니다. 정확한 필드와 검증 규칙은 소스 코드를 기준으로 확인합니다.

## 환경 변수 설정

API 키는 소스 코드에 직접 넣지 않고 Vercel 프로젝트의 환경 변수로 관리합니다.

| 변수명 | 필수 여부 | 용도 및 기본값 |
|---|---|---|
| `GROQ_API_KEY` | 필수 | Groq API 인증 키 |
| `GROQ_MODEL` | 선택 | 질문 모델. 기본값 `openai/gpt-oss-120b` |
| `GROQ_BACKUP_MODEL` | 선택 | 예비 질문 모델. 기본값 `openai/gpt-oss-20b` |
| `GEMINI_API_KEY` | 선택 | 완성품 도트 그림 생성용 키. 미설정 시 이모지 그림으로 대체 |
| `GEMINI_ART_MODEL` | 선택 | 그림 모델. 기본값 `gemini-3.5-flash` |
| `GEMINI_ART_BACKUP_MODEL` | 선택 | 예비 그림 모델. 기본값 `gemini-3.1-flash-lite` |

### Vercel에서 설정하기
1. Vercel에서 프로젝트를 엽니다.
2. **Settings → Environment Variables**로 이동합니다.
3. 필요한 변수명과 값을 등록합니다.
4. 변경 사항을 적용하려면 프로젝트를 재배포합니다.

무료 API 등급은 모델별 분당·일일 사용량 한도가 있습니다. 한도를 초과하면 요청이 실패할 수 있으며, 서비스는 가능한 경우 안내 메시지나 대체 모델을 사용합니다.

## 오류 처리 및 안정성

외부 AI API는 사용량 한도, 일시적인 서버 혼잡, 응답 지연 등의 영향을 받을 수 있습니다.

- **429:** 요청 한도 초과. 예비 모델 전환 등 가능한 대체 경로 활용
- **502 / 503:** 서버 오류 또는 일시적인 혼잡에 대한 재시도
- **504 / 지연:** 요청 시간 제한 및 지연 안내
- **이미지 생성 실패:** 유효하지 않은 도트 그림 대신 이모지 그림 표시
- **필수 입력 누락:** 게임 종류 미선택 등 사용자 입력 오류 안내

기존 구현 설명 기준으로 8초 이상 지연 시 안내하고 최대 45초 타임아웃을 적용하며, 서버 혼잡 시 1초·2초 간격으로 재시도합니다. 실제 적용 범위는 배포된 코드와 설정을 기준으로 확인합니다.

## 개발 과정에서 해결한 문제

### 1. 질문 생성 모델 변경
- 처음에는 Google Gemini API를 사용했으나, 사용하려던 모델에서 404 오류가 발생해 모델 변경이 필요했습니다.
- 이후 응답 지연(504)과 서버 혼잡(503)이 반복되어 질문 생성 역할을 Groq API로 분리했습니다.
- Groq의 Llama 3.3 모델에서 서비스 종료에 따른 502 오류가 발생한 뒤, 지원 모델 목록을 확인하고 `openai/gpt-oss-120b`로 변경했습니다.

### 2. 질문과 그림 생성 역할 분리
AI에게 질문과 도트 그림을 모두 생성하게 하자 응답이 길어지고 무료 사용량 초과(429)가 발생했습니다. 질문 생성은 Groq, 완성품 그림 생성은 Gemini가 담당하도록 역할을 분리했습니다.

### 3. 이미지 품질 개선
- 초기 이미지 모델이 감자튀김을 노란 네모 하나처럼 표현하는 문제가 있었습니다.
- 이미지 모델의 우선순위를 조정하고, 프롬프트에 실루엣 중심으로 그리라는 규칙과 예시를 추가했습니다.
- 서버에서 단색으로 꽉 찬 사각형 등 부적절한 그림 형식을 걸러내도록 개선했습니다.
- 대상에 맞는 이모지가 있으면 이모지를 사용하고, 적절한 이모지가 없을 때만 AI 그림을 생성하도록 변경했습니다. 이 방식은 결과 품질 편차와 API 사용량을 함께 줄이는 데 도움이 됩니다.

### 4. 너구리 캐릭터와 애니메이션 개선
- 기본·작업·성공·실패 상태의 너구리 이미지를 준비해 상황에 맞게 표시했습니다.
- 망치질 장면이 기본 캐릭터와 자연스럽게 이어지도록 같은 얼굴의 캐릭터 이미지를 기준으로 들기·내리치기 장면을 구성했습니다.
- 캐릭터가 배경과 따로 노는 느낌을 줄이기 위해 도트 칸 크기는 유지하고 색상 수를 줄여 시각 스타일을 통일했습니다.
- 운영체제의 애니메이션 감소 설정이 켜져 있을 때 이미지가 제때 표시되지 않는 문제를 확인하고, 이미지 파일이 로드된 뒤 다시 그리도록 수정했습니다.

### 5. 사용량 한도 대응
질문을 빠르게 연속 요청하면 모델의 분당 토큰 한도에 도달할 수 있습니다. 이를 고려해 기본 모델이 한도에 걸리는 경우 예비 모델 `openai/gpt-oss-20b`로 전환하도록 구성했습니다.

밤티공방의 콘셉트는 AI 결과의 작은 허점까지 유머로 받아들이는 데 있습니다. 다만 게임의 핵심 기능과 사용성을 해치는 오류는 개선 대상으로 구분합니다. 위 개발 기록은 주요 이슈를 요약한 것이며, 상세 구현과 변경 사항은 실제 소스 코드 및 커밋 기록을 기준으로 확인합니다.

## 배포 방법

1. 소스 코드를 GitHub 저장소에 올립니다.
2. Vercel에서 **Add New → Project**를 선택합니다.
3. GitHub 저장소를 Import합니다.
4. 필수 환경 변수 `GROQ_API_KEY`를 등록합니다. 그림 생성 기능을 사용하려면 `GEMINI_API_KEY`도 등록합니다.
5. Deploy를 실행합니다.
6. GitHub에 코드를 업데이트하면 Vercel이 자동 재배포하도록 설정할 수 있습니다.

## 로컬 실행

Node.js와 Vercel CLI가 필요합니다.

```bash
npm install -g vercel
vercel dev
```

프로젝트 폴더의 `.env` 파일에 필요한 키를 설정할 수 있습니다.

```env
GROQ_API_KEY=발급받은_키
```

이미지 생성 기능도 테스트하려면 `GEMINI_API_KEY`를 추가합니다. `.env` 파일이 공개 저장소에 올라가지 않도록 `.gitignore` 설정을 확인합니다.

## 테스트 및 확인 사항

모바일 브라우저에서 메인 화면과 게임 결과 화면을 확인했습니다.

- 메인 화면과 게임 시작 동선
- 모바일 화면에서의 레이아웃과 캐릭터 표시
- 질문과 답변의 진행 흐름
- 남은 질문 횟수 표시
- AI 추리 결과와 완성품 표시
- 새 게임으로 이어지는 동선
- 이미지 생성 결과의 표시

모든 기기와 브라우저, 모든 API 오류 조건을 빠짐없이 검증했다고 단정하지 않습니다. 실제로 확인한 범위를 기준으로 테스트 결과를 기록합니다.

## 한계와 향후 개선 방향

- AI가 정답을 추리하는 질문 전략과 일관성 개선
- 음식·사물별 도트 그림 생성 품질 개선
- API 사용량 한도 및 서버 혼잡 상황에서의 안내 강화
- 다양한 화면 크기와 브라우저에서 추가 테스트
- 키보드 조작 및 접근성 개선
- 응답 시간과 API 사용량을 고려한 성능·비용 최적화

## 보안 유의 사항

- API 키를 HTML, JavaScript, 공개 README 또는 커밋 기록에 직접 넣지 않습니다.
- API 키가 노출된 것으로 의심되면 제공사 콘솔에서 즉시 폐기하고 새 키를 발급합니다.
- 새 키를 Vercel 환경 변수에 등록한 뒤 재배포합니다.
- `.env` 파일이 GitHub에 올라가지 않도록 `.gitignore`를 확인합니다.
